# WAKUWAKU ISLAND 課題管理運用

更新日: 2026-08-13

## 目的

WAKUWAKU ISLAND のゲーム改善・サイト改善・実装・検証で発生する未解決事項を、レビューから実装完了まで一貫して追跡する。

## 正本

プロジェクト横断の課題管理は Notion の **「制作・開発 課題管理」** を正本とする。

- プロジェクト: `WAKUWAKU ISLAND`
- GitHub Issues はコード単位で必要な場合の補助管理とする
- Notion の内部 URL / database ID / 認証情報は、この公開リポジトリへ記載しない

## 登録対象

以下のうち、後続対応または完了確認が必要なものを登録する。

- UI/UX、ゲーム性、バグ、表示崩れ、操作性、スマホ対応
- BGM/SE、サムネ、ゲームカード、SEO、導線の未解決改善
- 実装後に再レビューや実機確認が必要な事項
- 複数ゲームへ横展開すべき再発防止事項
- Claude Code / Codex / ChatGPT のレビューで見つかった未解決事項

その場で修正・検証まで完了した軽微事項は原則登録しない。同一課題は重複登録せず、既存項目の状態・メモ・次のアクションを更新する。

## Notion 標準項目

- 課題名
- プロジェクト
- 対象
- 種別
- 優先度
- 状態
- 発見日
- 次のアクション
- 関連URL
- メモ
- 完了日
- 登録元

### 種別の主な使い分け

- `UI/UX`
- `ゲーム性`
- `バグ`
- `実装`
- `BGM/SE`
- `サムネ`
- `分析`
- `企画`
- `運用`

### 優先度

- `緊急`: 公開停止、重大破綻、データ損失、安全性など即時対応
- `高`: 公開品質、ゲーム成立性、主要ユーザー体験へ大きく影響
- `中`: 次回更新で直すべき品質改善
- `低`: 磨き込み、将来候補

### 状態

`未着手` → `検討中` / `実装中` → `確認待ち` → `完了`

後回しは `保留` とし、保留理由または再開条件を残す。

## 標準フロー

1. ChatGPT / Claude Code / Codex のレビューまたは実装中に課題を検出する
2. 課題名、対象ゲーム、種別、優先度、次のアクションを整理して Notion へ登録する
3. 実装着手時に `実装中` へ更新する
4. コード変更・ブラウザ検証後は `確認待ち` とする
5. ユーザー確認または必要な実測が通ったら `完了` とし、完了日と結果を残す
6. push 済みの場合は、必要に応じて commit / PR 情報を関連URLまたはメモへ残す

## 完了条件

**コードを書いただけでは完了にしない。** 変更対象に応じて必要な検証を行う。

- 実ゲームの主要フローが成立している
- PC / スマホで重大な表示崩れがない
- console error がない
- 保存・進捗・BGM/SE など、変更対象の回帰確認ができている
- 必要なゲームカード、SEO、React wrapper、iframe 切替などが実際に反映されている
- ユーザーが指摘した主要課題が目視または実測で解消している

## AI エージェント運用

### 作業開始時

- 対象ゲーム・機能に既知の未完了課題がある場合、それを先に確認して作業範囲を明確にする
- 指示文に未解決課題が含まれている場合、勝手に範囲を縮小しない

### 作業中

- 新しい未解決問題を見つけた場合、無視せず課題候補として残す
- その場で直す場合でも、別の回帰確認が必要なら完了扱いにしない

### 作業完了時

- 実装内容と実測結果を報告する
- 未解決事項が残る場合は明記する
- ユーザー確認待ちのものは `確認待ち`、実測まで完了したものだけ `完了` とする

## 役割分担

- **Git / GitHub**: コードと変更履歴の正本
- **Notion**: 未解決課題、優先順位、状態、次のアクションの正本
- **このドキュメント**: 課題管理の運用ルールの正本

課題の詳細を公開 GitHub に複製しすぎない。Notion に非公開情報がある場合は、公開リポジトリには必要最小限の一般化した内容だけを残す。
