# わくわくレジ 設計書

おみせの てんいんさん ごっこ。お客さんの注文どおりに商品をかごに入れ、レジで読み取り、おつりを渡す、小学校低学年向けのブラウザゲームです。おしごと体験シリーズの1本目です。

## 1. 概要

| 項目 | 内容 |
|---|---|
| ファイル | `wakuwaku-reji.html`（1ファイル完結、約920行） |
| 対象 | 6〜8歳（小学校低学年） |
| 端末 | スマホ・タブレット（タッチ）。縦・横の両方に対応。PC のマウスでも遊べる |
| 1回の長さ | お客さん5人、約3〜5分 |
| 外部依存 | Google Fonts のみ（読み込めない場合は端末の丸ゴシックで表示） |
| 画像・音声ファイル | なし。絵は絵文字と CSS、音は Web Audio API で合成 |
| 個人情報 | 扱わない。保存は端末の localStorage のみで、外部送信なし |

学びの要素は2つです。注文を読んで正しい商品と個数を選ぶこと（読解・数）と、合計とおつりを計算して硬貨を組み合わせること（たし算・ひき算・お金の扱い）です。

## 2. 画面と流れ

```
タイトル ──あそぶ！──▶ おみせえらび ──おみせを ひらく！──▶ ゲーム（5人） ──▶ けっか
   ▲                     ▲   │                          │ 🏠→しめる          │
   └──────◀──────────────┘   └──────────◀──────────────┘                    │
                              ▲──────────── おみせを えらぶ ◀───────────────┤
                              ゲーム ◀──────── もういっかい ◀────────────────┘
```

| 画面 | 役割 |
|---|---|
| タイトル | ロゴ、レジのイラスト、浮遊する商品、音のオン・オフ |
| おみせえらび | お店（3種）とレベル（3段階）の選択、最高記録、かざりの進み具合 |
| ゲーム | HUD、お店の場面（お客さん・吹き出し・レジ・カウンター）、案内バー、操作パネル |
| けっか | お客さんごとの⭐、合計⭐、称号、売上、新しいかざりの解放 |
| 確認 | 🏠で「おみせを しめる？」。表示中はゲームの進行を止める |

## 3. 1人の接客の流れ（状態遷移）

`S.phase` で管理します。

```
arrive ─(0.85秒)─▶ order ─(全部そろう)─▶ busy-order ─(0.8秒)─▶ scan
  ─(全部ピッ)─▶ busy-scan ─(0.7秒)─▶ 合計表示 ─(1.5秒)─▶ お客さんが支払う ─▶ pay
  ─(おつり正解)─▶ done ─(3.1秒)─▶ 次のお客さん（5人目のあとは end）
```

| フェーズ | プレイヤーの操作 | 内容 |
|---|---|---|
| arrive | なし | お客さんが左から入店、来店ベル |
| order | 棚の商品をタップ | 吹き出しの注文（絵文字と ×個数）どおりにかごへ入れる |
| scan | かごの商品をタップ | 1つずつ「ピッ」。レジ表示に金額が足されていく |
| pay | 硬貨をタップしてトレイへ、「わたす！」 | おつりを渡す。トレイの硬貨はタップで戻せる |
| done | なし | ⭐獲得の演出、お客さん退店 |

`busy-*` と `done` の間は入力を受け付けないため、連打で二重に進むことはありません。

## 4. レベルとお金のルール

| | かんたん | ふつう | むずかしい |
|---|---|---|---|
| 商品の値段 | 1〜9円 | 8〜45円 | 50〜400円（10円単位） |
| 注文の種類数 | 1〜2 | 1〜3 | 2〜3 |
| 注文の合計個数 | 3まで | 3まで | 4まで |
| 合計金額の範囲 | 3〜29円 | 10〜95円 | 100〜990円 |
| お客さんが出すお金 | 10円玉（合計を超える最小の10円単位） | 50円玉（合計50円未満のとき45%）か100円玉 | 500円玉（合計500円未満のとき45%）か1000円札 |
| おつりに使う硬貨 | 1・10円 | 1・5・10・50円 | 10・50・100・500円 |
| おつりの表示 | 最初から金額を表示 | 式「100 − 63 = ？」。💡ヒントで答えを表示 | 同左 |

支払額は必ず合計より多くなるように決めているので、おつりが0円になることはありません。注文は条件に合うまで最大400回ランダムに作り直し、それでも決まらないときは安全な1品の注文にします。

## 5. 判定と得点

| 項目 | ルール |
|---|---|
| ミス | 注文にない商品、個数オーバー、おつりの金額違い（トレイが空のときはミスにしない） |
| ミス後の案内 | 何が違ったかを案内バーに表示。商品なら必要な商品を光らせ、おつりならヒントを自動で表示 |
| ⭐ | お客さん1人ごとに、ミス0回で3、1回で2、2回以上で1 |
| 称号（5人で最大15） | 15：スーパー てんちょう、12以上：てんちょう、8以上：ベテラン てんいん、それ未満：みならい てんいん |
| 売上 | 合計金額の累計。けっか画面と保存データに記録 |
| ゲームオーバー | なし。何度間違えても最後まで遊べる |

トレイに置ける硬貨は15枚までです。

## 6. ごほうび（お店のかざり）

これまでに集めた⭐の合計で、ゲーム画面のお店に飾りが増えます。

| 必要な⭐ | かざり | 表示 |
|---|---|---|
| 5 | 🎈 ふうせん | ひさしの下の左右で揺れる |
| 15 | 🌸 おはな | カウンターの上 |
| 30 | 💡 キラキラライト | ひさしの下で点滅する電球 |
| 50 | 🎀 リボン | ひさしの上 |
| 80 | 👑 きんの レジ | レジが金色になり、王冠がのる |

おみせえらび画面に次のかざりまでの残り⭐を、けっか画面に新しく解放したかざりを表示します。

## 7. お店のデータ

`SHOPS` に定義しています。値段は `p:[かんたん, ふつう, むずかしい]` です。

| お店 | 商品（かんたん / ふつう / むずかしい） |
|---|---|
| 🥕 やおや | にんじん 3/12/80、りんご 5/25/120、バナナ 4/18/150、トマト 2/15/90、きゅうり 1/8/60、ぶどう 8/35/300 |
| 🍭 おかしやさん | キャンディ 1/10/50、クッキー 3/15/100、チョコ 5/20/120、ドーナツ 6/25/150、ソフトクリーム 7/30/200、ケーキ 9/45/350 |
| 🧸 おもちゃやさん | ふうせん 2/10/100、ヨーヨー 4/20/150、ミニカー 5/25/250、ボール 6/30/300、ぬいぐるみ 8/40/350、ロボット 9/45/400 |

お客さんは12種類の動物（`CUSTS`）から、直前と同じにならないように選びます。

## 8. コードの構成

1つの即時関数の中に、次の順で書いています。

| 区画 | 主な関数・データ | 役割 |
|---|---|---|
| データ | `SHOPS` `LV` `CUSTS` `DECOR` `PRAISE` `THANKS` | ゲームの中身 |
| 保存 | `SAVE` `save()` | 読み込み時に型を確認し、壊れたデータは初期値に戻す |
| 音 | `ensureAudio` `tone` `sfx` `startBgm` `speak` `setMuted` | 効果音、BGM、読み上げ |
| 演出 | `confetti` `fly` `burst` `popText` `praise` `wig` | 紙ふぶき、飛ぶ商品と硬貨、キラキラ、ほめ言葉 |
| 状態 | `S` `later` `isPaused` | ゲーム全体の状態と、時間差の処理 |
| 画面 | `renderSelect` `applyShop` `updateDecor` `renderDots` `renderPanel` | 表示の更新 |
| 進行 | `startRound` `nextCustomer` `pickItem` `toScan` `scanItem` `showTotal` `customerPays` `addCoin` `giveChange` `success` `finishRound` | 接客の流れ |

### 時間差の処理

時間差で動く処理はすべて `later(fn, ms)` を通します。

- ラウンドを始めたり、お店を閉めたりするたびに `S.gid` を1増やします。`later` は登録時の `gid` と違えば何もしないので、前のラウンドの処理が次のラウンドに混ざりません。
- 確認画面の表示中と、ページが非表示のときは、`isPaused()` が真になり、0.25秒ごとに待ち続けます。そのため、確認画面の裏でお客さんが進むことはありません。
- 商品や⭐が飛ぶアニメーションの完了時の処理も、開始時の `gid` を確認します。

### 画面レイアウト

ゲーム画面は CSS グリッドです。縦向きは「HUD／お店の場面／案内バー／操作パネル」の縦1列、横向き（縦横比 5:4 以上）は左にお店の場面、右に案内バーと操作パネルを並べます。

- 幅360px以下では HUD を縮め、高さ420px以下では操作パネルを詰めます。
- 注文が3種類のときは、吹き出しの絵文字を小さくして収めます。
- `viewport-fit=cover` と `env(safe-area-inset-*)` で、ノッチやホームバーを避けます。
- 操作パネルやメニューは端末のダークモードに合わせて色を変えます。お店の場面は常に明るい配色です。
- `prefers-reduced-motion` が有効なときは、常に動くアニメーションを止め、紙ふぶきなどを減らします。

## 9. 演出と音

| 場面 | 演出 | 音 |
|---|---|---|
| 来店 | 左から入ってきて止まる | ピンポン（2音） |
| 商品を選ぶ | 商品がかごへ弧を描いて飛ぶ、キラキラ | ポン |
| 間違い | ボタンとお客さんが揺れる、案内バーがオレンジに | ブー |
| ピッ | 商品がレジへ飛ぶ、スキャナーが光る、「+12えん」が浮かぶ | ピッ（矩形波） |
| 合計 | レジ表示が点滅 | チャリン |
| 支払い | お金がお客さんからカウンターへ飛ぶ | チャリン |
| 正解 | 紙ふぶき、⭐とほめ言葉、ハート、⭐が HUD へ飛ぶ | チーン、ファンファーレ |
| けっか | 紙ふぶき、⭐の数をカウントアップ | ファンファーレ |

- BGM は 32ステップの明るいメロディとベースを、0.09秒ごとの先読みで鳴らします。遅れた場合は現在の時刻に合わせ直すので、画面に戻ったときに音がまとめて鳴ることはありません。
- 読み上げ（`speechSynthesis`、日本語）は、注文、合計金額、お客さんの支払い、お礼、けっかで使います。🔊ボタンで音と一緒にオフになります。
- iPhone では、最初のタップ（「あそぶ！」）で音と読み上げを有効にし、以降もタップのたびに音声の再開を試みます。

## 10. 保存データ

localStorage のキー `wakuwaku-reji-v1` に JSON で保存します。読み書きはすべて try/catch で囲み、保存できない環境でも遊べます。

```json
{ "stars": 42, "sales": 3180, "best": { "yaoya1": 15, "okashi3": 11 }, "shop": "okashi", "level": 3 }
```

| キー | 内容 |
|---|---|
| stars | これまでの⭐の合計（かざりの解放に使う） |
| sales | これまでの売上の合計 |
| best | お店とレベルごとの最高⭐（例：`yaoya1` はやおやのかんたん） |
| shop / level | 最後に選んだお店とレベル（次回の初期選択） |

## 11. レビューで直した点

| 内容 | 影響 | 対応 |
|---|---|---|
| 確認画面の表示中もゲームが進んでいた | 「つづける」を押すまでに、お客さんが入れ替わったり、けっか画面に進んだりする | 確認画面とページ非表示の間は、時間差の処理を止める |
| 間違えたボタンの揺れ用クラスが残っていた | 一度間違えた商品は、次に間違えても光る案内が出ない | 揺れが終わったらクラスを外す |
| 途中でやめて、すぐ開き直したときの⭐ | 前のラウンドで飛んでいた⭐が、新しいラウンドの⭐表示に加算されることがある | ⭐が届いたときにラウンド番号を確認する |
| 保存データが壊れているときの最高記録 | 「⭐NaN」と表示される可能性 | 数値に変換し、変換できなければ0にする |
| iPhone で読み上げが鳴らない可能性 | 最初の読み上げがタップ操作の外で始まるため、iOS が止めることがある | 「あそぶ！」のタップで最初の読み上げを行い、許可を得る |
| iPhone でアプリ切り替え後に音が戻らない可能性 | BGM と効果音が鳴らなくなる | タップのたびに音声の再開を試みる |
| 個数の表示「0/2」 | 分数のように見えて、低学年には分かりにくい | 「×2」と、取った数を●○で表示 |
| 注文3種類で吹き出しがあふれる可能性 | 小さいスマホで絵文字がカウンターに重なる | 3種類のときは絵文字を小さくする |
| 幅320pxのスマホで右端が切れていた（初版の確認時） | 「わたす！」ボタンや硬貨が押せない | グリッドの列幅を画面幅に固定し、ボタンを縮める |

## 12. テスト

ヘッドレス Chromium（Playwright、タッチ有効）で確認しました。

| 確認内容 | 結果 |
|---|---|
| 画面サイズ 390×844、320×568、844×390、1024×768 で、3つのお店と3つのレベルを5人分通して遊ぶ | エラーなし、けっか画面まで進む |
| 毎回わざと1回間違える | ⭐が2ずつ入り、合計10になる。必要な商品が光る |
| レジに読み取った金額の合計と、注文の合計金額 | 全接客で一致 |
| 確認画面を5秒開いたままにする | お客さんの番号が進まない。「つづける」で再開する |
| 途中でお店を閉め、すぐ開き直す | ⭐の表示が0から始まり、正常に進む |
| 壊れた保存データ（⭐が文字列、存在しないお店とレベル）で起動 | 初期値で起動し、記録も正しく保存される |
| 注文3種類（1つは×2）を幅320pxで表示 | 吹き出しの中に収まる |

まだ確認していないこと：実機での音と読み上げの聞こえ方、指での操作感、古い端末での動作の重さ。

## 13. 既知の制約

- iPhone のマナーモードがオンのときは、効果音と BGM が鳴りません（iOS の仕様）。読み上げは端末によって聞こえます。
- 日本語の音声が入っていない端末では、読み上げが行われないか、正しく読めません。
- 絵文字は端末のフォントで表示するため、機種によって見た目が変わります。古い端末では 🪀（ヨーヨー）が表示されない可能性があります。
- 保存データは端末とブラウザごとです。兄弟で1台を使うと、⭐とかざりは共有になります。
- 硬貨は数字と色で区別したオリジナルの絵で、実際の硬貨の図柄は使っていません。

## 14. 調整と拡張のしかた

| やりたいこと | 変更する場所 |
|---|---|
| 値段を変える | `SHOPS` の各商品の `p`（かんたん・ふつう・むずかしいの順） |
| 注文の量や金額の範囲を変える | `LV` の `kinds` `maxItems` `minTotal` `maxTotal` |
| おつりに使う硬貨を変える | `LV` の `drawer` |
| お客さんの支払い方を変える | `makePay()` と `payList()` |
| お店を追加する | `SHOPS` に1件追加（名前、絵文字、色 `c`、濃い色 `d`、説明、商品6つ）。選択画面と棚は自動で増える。カードは3列なので、4店以上なら `.shops` の列数も変える |
| 1回のお客さんの数 | `NUM`（けっか画面の「/ 15」も合わせて変える） |
| ⭐の基準 | `success()` の `st` の計算 |
| 称号 | `rankOf()` |
| かざりを増やす | `DECOR` に追加し、HTML に `.deco d-◯◯` 要素、CSS に `.scene.has-◯◯ .d-◯◯` の表示ルールを追加 |
| BGM | `MEL`（MIDI ノート番号、32ステップ）と `BASS` |

拡張のアイデアとしては、お客さんが小銭を足して出す支払い（例：63円に113円を出す）、ポイントカードやレシートを渡す演出、制限時間つきのラッシュモード、ほかのおしごとゲームと共通の「おしごとスタンプ帳」などが考えられます。
